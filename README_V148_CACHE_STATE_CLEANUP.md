# v149 缓存 URI 与孤儿文件清理修复

## v148 为什么没有解决

搜索缓存写入用户选择的文件夹后，旧代码使用文件提供器返回的文件长度判断是否完成。部分 Android 文件提供器会在刚写完时暂时返回长度 0，即使文件实际上存在并且可以正常播放。

随后旧代码把这次结果当成缓存失败：

1. 搜索缓存方法抛出异常，没有把缓存 URI 写回当前歌曲；
2. 删除缓存键时可能只删掉元数据，没有删掉友好名称音频；
3. 加入歌单拿不到缓存 URI，因此继续提示缓存未完成；
4. 扫把依赖已经被删除的元数据，因此也找不到残留音频。

这条链路能同时解释“文件存在且能播放，但提示缓存未完成”和“未加入歌单的缓存清理不掉”。

## v149 修改

- 新增 `CacheFileState`：`content://` 缓存通过打开输入流并读取至少一个字节确认，不依赖文件长度；短暂不可见时会重试。
- 搜索缓存写入后通过可读性确认；失败时直接删除实际 URI，再删除元数据，避免继续制造孤儿。
- 加入歌单统一使用相同的 URI 可读性检查。
- 扫把直接读取已保存歌单中的 `cachedUri` 和 `uri`，保留歌单真实引用的文件。
- 扫把除按元数据清理外，还会删除没有元数据的旧友好名称孤儿音频、歌词和临时文件。
- 下载后的临时文件仍须通过解密和真实音轨验证；加密 M4A 仍不会被当作完成缓存。
